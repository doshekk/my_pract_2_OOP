# Tourism Simulation System

## Опис

Це імітаційна програма системи туризму, розроблена на Java з використанням:
- **Object-Oriented Programming (OOP)** - спадкування, поліморфізм, абстрактні класи, інтерфейси
- **Design Patterns** - использование композиції та агрегації
- **Google Guice** - впровадження залежностей через конструктор
- **SQLite** - збереження даних в локальній базі даних

## Архітектура

### Класи та їхні взаємозв'язки

**Ієрархія успадкування:**
- `TravelSubject` (абстрактний клас) реалізує `IBookingPlacement`
  - `Tourist` (турист)
  - `Manager` (менеджер)
  - `Admin` (адміністратор)

**Композиція та агрегація:**
- `Booking` **композиція** з `BookingItem` (один `Booking` містить один `BookingItem`)
- `Booking` **агрегація** з `BookingService` (впровадження через конструктор)
- `Tourist` **агрегація** з `Booking` (турист може мати бронювання)

### Google Guice впровадження залежностей

Класи, що використовують впровадження залежностей:
- `Booking` отримує `BookingService` через конструктор
- `BookingService` отримує `Connection` (SQLite) через конструктор
- `Connection` налаштовується в `TourismModule` з JDBC URL та ініціалізацією таблиці

### База даних

Таблиця `booking_items`:
- `id` - унікальний ідентифікатор (автоінкремент)
- `room_type` - тип номера (TEXT)
- `price` - ціна бронювання (REAL)
- `created_at` - час створення запису (TIMESTAMP, за замовчуванням поточний час)

## Основні концепції OOP, реалізовані в програмі

1. **Спадкування** - класи `Tourist`, `Manager`, `Admin` спадкують від `TravelSubject`
2. **Поліморфізм** - кожен клас перевизначає метод `showRole()` та методи інтерфейсу
3. **Інкапсуляція** - кожен клас має приватні атрибути та публічні методи доступу
4. **Абстрактність** - `TravelSubject` є абстрактним класом з абстрактним методом
5. **Композиція** - `Booking` містить об'єкт `BookingItem`
6. **Агрегація** - `Tourist` може мати об'єкт `Booking`, який може існувати незалежно
7. **Впровадження залежностей** - використання Google Guice для управління залежностями
